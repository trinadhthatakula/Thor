Bulk actions · phase 3

Keep slow work in its own lane.

A worker split alone cannot unblock Thor. The root cause is Odin’s single cached shell FIFO. This design isolates interactive, archive, and sweep commands while keeping WorkManager’s two durable chains.

01

Verified diagnosis

Archive Workers and Freezer unfreeze reach the same singleton ShellRepository. Odin’s cached MainShell owns one FIFO and cannot begin a later package command until the active tar or extraction command returns.

Unfreeze is not currently a Worker, so changing WorkManager’s executor, adding a second chain, or adding another foreground service does not remove this queue.

The animation is a second defect. performCountedFreeze marks completion only after its loop. Cancellation or an unexpected throw can leave the dialog visible and incomplete forever, even after the shell operation has ended.
What was ruled out

Thor injects ordinary Dispatchers.IO; Odin waits through a callback rather than pinning a thread. Archive tar/extract holds no Room transaction, and WorkManager closes its own database transaction before the Worker body starts. Dispatcher starvation and Room write locking do not explain this reproduction.

03

Two schedulers, three root lanes

WorkManager determines when durable work runs. The root router determines which privileged process receives its commands. A dispatcher is not a lane: two dispatchers calling getShellAwait() still converge on MainShell.

Interactive

Immediate user-facing package actions. Existing MainShell stays the default for call sites not explicitly migrated.

  • No archive commands
  • No Worker sweep commands
  • Fast failure in degraded conflicts

Archive

Every root shell boundary owned by backup and restore—not only tar creation.

  • List and verify
  • Tar and extract
  • Swap and ownership repair
  • Privileged cleanup

Sweep

One command at a time for replay-safe package mutations on THOR_SWEEP_CHAIN.

  • Freeze / unfreeze
  • Per-app cache clear
  • Reinstall / Fix Store
Odin already supports this. Shell.Builder.create().build() creates another su process with independent streams and a private task deque. A second RealShellRepository is not enough because it still resolves the cached MainShell.
04

Owned shell lifecycle

Thor passes an explicit PrivilegeExecutionLane through the privileged operation boundary. It is not hidden in a dispatcher or coroutine-context element. Root routes it; Shizuku and Dhizuku may ignore it in this cut.

01AcquireA cancellable outer mutex ensures no second Odin task is queued.
02Build lazilyCreate or reuse the lane’s healthy shell generation.
03Execute onceSubmit one job, record queue wait and command duration.
04Retire safelyOn cancel or transport death, close only the generation this operation owns.
A coroutine timeout is not cancellation by itself. An active dedicated command must invalidate and close its shell. The next command gets a fresh generation. Mutating commands are never automatically retried after an unknown transport outcome.
Timeout policy

Sweep items retain the existing 30-second deadline, but expiry now closes the sweep shell so a timed-out command cannot execute later. Archive tar/extract has no fixed wall-clock limit because legitimate duration scales with data size. The user’s cancel action must still terminate the owned archive generation.

Device validation must prove closing su also terminates the active child. If tar survives, PID-scoped child termination from a fresh control shell is required before cancellation can claim success.

05

Concurrency where it is safe

A process-singleton package coordinator owns keyed leases. Archive backup and restore hold an exclusive lease for the full operation. Sweeps hold one package only while acting on it. Different package names remain independent.

Durable sweep requests

The launcher snapshots operation metadata and canonical package names in Room, then puts only a request id in WorkManager Data. It rejects blanks, removes exact duplicates, and sorts with Kotlin’s locale-independent natural string order before assigning ordinals. The current BulkScope has Watchlist and Profile only; it does not have a Selection variant. Every surface resolves its scope before enqueue.

07

Worker lifecycle and truth

One generic PrivilegeSweepWorker owns the lifecycle; operation-specific functions own each package mutation. A single new PRIVILEGE_SWEEP value is appended to ThorJobKind so existing ordinal-derived notification ids do not move.

Progress

ThorJobStage.ACTING publishes processed/total. Root is sequential on one sweep shell; other transports retain only proven bounded concurrency.

Cancellation

APPEND_OR_REPLACE propagates active cancellation to dependent successors, so the first cut labels this action “Cancel sweep queue.” Every affected request becomes terminal; partial counts use noteResult.

Replay

No operation-level Result.retry(). Process death may still rerun work, which is why every admitted operation must be replay-safe.

total = succeeded + failed + busy + unresolved

08

UI state follows the job

Migrated Freezer actions launch a durable request and observe Worker state. The dialog no longer owns an unguarded action loop. Rotation or process recreation reconnects by request/work id rather than launching again.

  • Success completes and auto-dismisses.
  • Failures and busy items complete but remain visible.
  • Cancellation shows partial and unresolved counts.
  • Launch failure clears running state immediately.
  • Unexpected observer failure reaches a terminal error.
  • The legacy path gains an independent try/finally repair.
09

Proof before rollout

JVM contract tests
  • A blocked archive lane does not delay interactive or sweep executors.
  • One lane stays serial; a pre-lease cancellation submits nothing.
  • Active cancellation retires only the owning generation.
  • Transport death does not retry a mutation.
  • Package leases block only matching packages.
  • Request snapshots survive recreation and bypass the WorkManager Data size limit.
  • Force-stop and uninstall cannot be encoded as sweep operations.
  • Every Freezer completion path becomes terminal.
Physical root-manager gate
  1. Create MainShell, archive shell, and sweep shell on available Magisk, KernelSU, and APatch devices.
  2. Verify authorization, uid, namespace, SELinux access, and paths.
  3. Hold a slow archive; complete unrelated interactive unfreeze and a sweep.
  4. Reject a same-package mutation visibly.
  5. Cancel archive; prove the child process is gone and staging cleanup completed.
  6. Recreate one dedicated shell without affecting the other two.
  7. Kill Thor during each Worker class and verify replay.
The root change does not ship from JVM evidence alone. Concurrent su policy, child-process death, namespaces, and SELinux access are device facts.

11

Acceptance criteria

  • Long root archives cannot occupy interactive or sweep shells.
  • Unrelated unfreeze completes during backup/restore.
  • Same-package conflicts are bounded and explained.
  • Cancellation stops the underlying child on validated devices.
  • No cancelled queued command executes later.
  • Sweeps survive Activity recreation and ordinary process death.
  • Sweeps do not use a foreground service.
  • Notification-disabled users receive no invisible durable work.
  • Partial counts remain truthful.
  • Force-stop and uninstall remain outside WorkManager.
  • Job and sweep chains remain independently serialized.
  • The Freezer UI reaches a terminal state on every path.
