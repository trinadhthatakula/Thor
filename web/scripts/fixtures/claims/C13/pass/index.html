Writing an extension

AutomationExtension still ships in the contract, in both the classes jar and the sources jar, and the template's entry class still implements it. What changed is that Thor no longer dispatches to it.

The old path broadcast to onTrigger, which coupled an extension's classloader to Thor's own process. A content provider replaced it, and Thor now casts a loaded entry class to ThorExtension.

So implement ThorExtension for anything you want Thor to load, and treat the automation interface as inert rather than absent.
